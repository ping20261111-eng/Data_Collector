# 数据文件夹列表 · 三列展示规范（v6.9.6）

> 范围：`查看数据` 页左侧「数据文件夹」列表的一行三列 —— **名字 / 录制时间 / 判定**。
> 依据：现场 2026-10-28 的三条要求 + 2026-10-29 的补充（"结果和时间从右开始排，
> 左边的空间全部用来显示包名"）。
> 实现：`ui/bag_verdict.py`（取值与列位，纯函数）+ `ui/bag_row_delegate.py`（绘制）。

---

## 一、四条要求怎么落到像素上

| 现场要求 | 设计决断 | 验收判据（自动化） |
|---|---|---|
| ① 名称显示全部 | 名字列**下限** = 全场最长名字的自然宽度；实际宽度 = 左侧全部剩余空间 | `test_column_layout_never_shrinks_the_name_column`、`test_long_bag_names_are_not_elided_in_the_real_dialog` |
| ② 时间戳到秒 | `MM-DD HH:MM:SS`；列宽按**带秒的真实时间戳**量 | `test_stamp_column_has_room_for_seconds` |
| ③ 合格绿 / 不合格红 / 未验证黑 | 判定列三态三色；不合格时名字列同步转红、行底叠 10% 淡红 | `test_verdict_color_follows_the_three_states`、`test_failed_row_gets_a_tinted_background` |
| ④ **时间与判定靠右，左边全给名字** | 列位从右边推：`verdict_x = 行宽 - hpad - verdict_w` | `test_column_layout_puts_the_last_two_columns_at_the_right_edge` |

**为什么不能用省略号兜底**：截断后 `rosbag2_202610…` 这一屏几行**完全相同**，
名字列就不携带任何信息。名字是"这是哪一包数据"的唯一标识，宁可整行变宽、横向滚动，
也不能把标识切掉。

## 三、三态视觉

| 状态 | 名字列 | 时间列 | 判定列 | 行底 |
|---|---|---|---|---|
| 合格 | 正文色 | 正文色 | **绿** | 原样（白 / 隔行浅灰） |
| 不合格 | **红** | 正文色 | **红** | 叠加 `danger` 10% |
| 未验证 / 待验证 | 正文色 | 正文色 | 正文色（黑） | 原样 |
| 选中（任意态） | `highlightedText` | `highlightedText` | `highlightedText` | 样式选中底色（不叠淡红） |

三条取舍：**时间列不跟着红**（它是对时间线的中性事实）；**合格只在判定列绿**
（整行染绿会让名字与时间失去对比）；**选中态让位给 `highlightedText`**
（选中底色是主题强调色，红压上去对比度不够，而"合格/不合格"本身已经把语义说清了）。

## 四、列位规格（像素，设计稿 1.0 基准）

```
│←hpad 10→│              名字列（吃掉左边全部剩余）              │←gap 16→│ 时间列 │←gap 16→│ 判定列 │←hpad 10→│
```

列位**从右边推**：

```
verdict_x = 行宽 − hpad − verdict_w
stamp_x   = verdict_x − gap − stamp_w
名字列宽   = 剩余宽度，且不低于「最长名字的自然宽度」
```

- **名字列**：下限 = 最长名字自然宽度 + 4px 余量（再小就会被截）；上限 = 左边全部剩余。
- **时间列**：按行内实际时间戳里最宽的那个量。
- **判定列**：按**最长文案**（「不合格」3 个汉字）预留，内容左对齐。

实测（26 字符名字 + `MM-DD HH:MM:SS` + 「不合格」，设计稿 1.0）：

| 元素 | 需要宽度 |
|---|---|
| 名字（`cloth_rack_20261027120000`） | 247px |
| 时间（`10-27 12:00:00`） | 131px |
| 判定（「不合格」） | 51px |
| 两段间距 + 左右留白 | 2×16 + 2×10 = 52px |
| **一行下限合计** | **481px** |

视口比这个宽 → 多出来的宽度**全给名字**（右侧两列贴着右边缘）；
比这个窄 → 整行取这个宽度、视图横向滚动，不截断任何一列。

- 行高：`字体高 + 2×8px`，且 **≥ 32px**（触摸可点目标的短边门槛）。
- 字号：`fs_sm = 12`，三列同字号 —— 判定靠颜色与位置区分，不靠字号跳出来。

## 五、无障碍

| 项 | 做法 |
|---|---|
| 对比度 | 三态文字色全部 ≥ 4.5:1（含行底纹叠加后的复合色） |
| 不只靠颜色 | 判定列本身就是文字（合格/不合格/未验证），色盲用户读字即可 |
| 触摸 | 行高 ≥ 32px；整行为点选区域 |
| 键盘 | 沿用列表原生行为，自绘不拦截键盘 |
| 屏读/复制 | item 纯文本仍是 `名字␣␣␣␣时间␣␣␣␣判定`；`ForegroundRole` 保留"这一行是否不合格" |
| 提示 | hover 显示判定原因 + 报告文件名 |

## 六、实现要点（给维护者）

1. 🔴 **`painter.setFont(opt.font)` 不能省**。自绘时 painter 用的是**调用方给的字体**
   （视图/控件那套），而列宽是按 `opt.font` 量的。同机实测两者能差 20%
   （`IBM Plex Mono` 未安装时的回退、QSS、DPI 都会让它们分开）—— 量得窄、画得宽，
   右边就被列边界切掉。现场看到的 `rosbag2_20261027144…`、`04-12 07:47` 就是这么来的。
   守卫：`test_paint_leaves_the_painter_on_the_measuring_font`（直接问 painter 用的什么字体）。
2. **画之前核对列宽**（`_ensure_widths`）：字体指纹变了、或这一行装不下，就当场重量 ——
   因为 `fit_columns()` 是在窗口显示前量的一次，之后字体可能被样式/DPI 换掉。
3. **状态从行文本第三段反推**（`bag_verdict.state()`），不另存字段。
4. **列宽只在整表刷新后量一次**；逐条更新（验证完成一条刷一条）不重排。
5. **delegate 不持有控件引用**：要用视口宽时只读 `option.widget` 当场取。
6. 底纹用 `danger` 叠 10% 透明度算出来，不写死色值 —— 暗色主题下才不会刺眼。
7. QPainter 仍走 try/finally 收尾；背景仍交 `drawControl(CE_ItemViewItem)`。

## 七、验收清单

- [x] 名字全显示（任意视口宽），窄窗口横向滚动而非截断
- [x] 时间到秒，且不再被列宽切掉
- [x] 合格绿 / 不合格红 / 未验证黑，红绿对比度 ≥ 4.5:1
- [x] 时间与判定贴右边缘，左边剩余空间全给名字

- [x] 选中态可读（`highlightedText`）
- [x] 行高 ≥ 32px
- [x] 画字与量宽用同一套字体（`painter.setFont`）

## 附：左侧「日志」列表（v6.9.7）

同一页里的日志列表只有两列，规则更简单：

```
│←hpad→│              文件名（吃掉剩余，放不下才省略）              │←gap→│ 时间（贴右边缘）│←hpad→│
```

- **时间不省略**：它是这一列的意义；宽度就是它自己的宽度，右边界恒为 `rect.right() - hpad`。
- **文件名可省略**：它只是标识，日志通常按时间读。
- 时间右边缘与文件名长短**无关** —— 守卫 `test_time_right_edge_is_the_same_for_any_file_name_length`
  用像素量：三种长度文件名的最后一行墨，右边缘差 ≤2px。
- 同样遵守上文两条纪律：`painter.setFont(opt.font)`、QPainter try/finally。
- 实现在 `ui/log_row_delegate.py`；样张 `docs/log-list-preview.png`。
